# SentinelPulse — Prototype MVP

AI-powered multi-signal population and workforce health early-warning demonstration.

## Current MVP scope
- Abu Dhabi-area demonstration locations (reference coordinates).
- Historical weather ingestion through the Open-Meteo Archive API (optional).
- Synthetic workplace exposure and aggregated health-service signals.
- Isolation Forest anomaly scoring.
- Transparent multi-signal risk fusion.
- Gradient-boosting forecast of next-hour synthetic service activity.
- Streamlit dashboard: command center, map, explainability, alerts/actions, validation.
- CSV export and guest access (no authentication).

## Important data and safety notes
- With **Use public historical weather** disabled, all data are synthetic.
- With it enabled, environmental observations are fetched from Open-Meteo; workplace and health-service signals remain synthetic.
- Synthetic injected events are used only to demonstrate back-testing mechanics. Reported metrics are not clinical validation.
- Approximate wet-bulb temperature is calculated using an approximation and is not WBGT.
- The application is not a diagnostic device and must not be used to make individual clinical, employment, insurance or disciplinary decisions.

## Run locally
Python 3.10+ recommended.

```bash
python -m venv .venv
source .venv/bin/activate        # macOS/Linux
pip install -r requirements.txt
streamlit run app.py
```

Open the local URL printed by Streamlit. No login is required.

## Deploy
1. Push this folder to a private or public GitHub repository.
2. Create a Streamlit Community Cloud app.
3. Select `app.py` as the entry point.
4. Add `requirements.txt` from this repository.
5. Deploy and test the public URL in an incognito browser.

Do not commit secrets or personal data. No API key is required for Open-Meteo's public historical endpoint.

## Data provenance
- Weather: Open-Meteo Historical Weather API — https://open-meteo.com/en/docs/historical-weather-api
- Workplace and service signals: synthetic data generated by `sentinelpulse/data.py`.
- Geographic points: illustrative area reference coordinates in `sentinelpulse/data.py`; replace/verify against an appropriately licensed boundary dataset before pilot use.

## ML engine refinement (v0.2.0)
- Isolation Forest is fitted on the earlier 70% of timestamps and scored across the series.
- Service deviations use one-sided, area-specific rolling robust baselines (up to 7 days); future observations are not used in each row's baseline.
- Risk fusion retains separate environmental, service, workplace and multivariate-anomaly components.
- Three-hour smoothing prioritizes persistent signals over isolated spikes.
- Validation metrics are calculated on the later temporal holdout against synthetic injected-event labels.
- Metrics remain synthetic demonstration evidence, not clinical or operational validation.


## Explainability refinement (v0.2.1)

- The latest unsmoothed hourly score is shown separately.
- Added a 48-hour hourly-versus-persistent risk trend.
- Component bars display numeric values and retain the distinction between component indices and clinical probabilities.
- Improved metric-card text contrast for dark-theme browser sessions.


## Predictive Heat-Risk Intelligence (v0.3.0)
- Adds a 24-hour area-level outlook and selectable +6h / +24h summaries.
- Uses recent same-hour historical medians for temperature, humidity, approximate wet-bulb, workload and shift exposure.
- Produces a transparent operational heat-exposure index and a historical-baseline confidence indicator.
- This is not a meteorological forecast, calibrated probability, individual health prediction, or validated occupational safety threshold.
- Operational use requires future-weather integration, rolling-origin backtesting and local validation.


## Live Weather Intelligence (v0.4.0)
- Adds Open-Meteo Forecast API ingestion for all five configured Abu Dhabi monitoring areas.
- Retrieves hourly 2 m temperature, relative humidity, 10 m wind speed and provider wet-bulb temperature.
- Calculates a transparent operational heat-risk index using live weather plus latest carried-forward synthetic workload/shift exposure.
- Adds manual refresh and a 24-hour forecast table/chart with risk tiers.
- Retains historical same-hour outlook as a clearly separated comparison.
- Public weather forecast is real external data; operational workload/shift inputs remain synthetic. Health-service signals are not forecast.
- Requires network access at runtime. API attribution and applicable Open-Meteo terms/licence must be respected.
- The operational index is not WBGT, a clinical probability, or a validated safety threshold.


## Live outlook operational-profile correction (v0.4.1)
- Replaces last-record carry-forward with area-specific historical median workload and shift-exposure profiles matched to each forecast hour.
- Prevents a latest night-shift exposure value from being applied unchanged to the following daytime forecast.
- Exposes workload and shift-exposure profile values in the live forecast table.
- These operational profiles remain synthetic demonstration data; they are not observed worker schedules or individual worker risk.


## Predictive AI layer (v0.5.0)
- Adds a dedicated Predictive AI tab with area-level peak risk, expected peak time, trajectory, weighted leading driver, context coverage and a proportionate operational response.
- Uses the live Open-Meteo weather forecast and hour-matched synthetic operational profiles.
- Driver attribution is a weighted component comparison, not causal inference. Context coverage is sample sufficiency, not a calibrated confidence probability.
- No clinical outcome, worker physiology or observed worker schedule is inferred. The feature is decision support for demonstration and requires local validation.


## Predictive intelligence refinements (v0.6.0)
- Separates net trajectory direction (rising/falling/stable) from the forecast's shape (morning peak, afternoon peak, sustained elevated exposure, or directional/stable pattern).
- Adds hourly duration above guarded, elevated and high operational-index thresholds.
- Adds a transparent weighted environment/workplace contribution split.
- Uses forecast timestamps to classify peak timing. Threshold-duration outputs count forecast slots and are not worker-level exposure measurements.
- Public weather is live when enabled; operational profiles remain synthetic and must be replaced/validated with authorized site data before operational use.

## Geographic risk differentiation (v0.7.0)
- Added five distinct, explicitly fictional workplace scenario archetypes to demonstrate how different workload and shift-exposure patterns can alter area-level outlooks.
- Preserved public forecast weather as the environmental input; synthetic scenario profiles remain a separate operational-context layer.
